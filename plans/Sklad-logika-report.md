# Система управления складом и отчётностью для автомойки

**Версия:** 2.0 (с отчётами для владельца)  
**Статус:** Финальная архитектура с отчётами  
**Дата:** 15 января 2026  
**Автор:** Система CRM для автомойки

---

## 1. Общая концепция

### Основной принцип: Динамический максимум + Логирование всех операций

- **current_qty** — сколько сейчас на складе (реальное число)
- **last_peak_qty** — максимум после последней закупки (становится 100% на прогресс-баре)
- **Ревизия** — админ вводит реальный остаток, система логирует разницу
- **Отчёты** — система автоматически считает расход, себестоимость, потери, прогнозы

Чем это решает:
- Не нужны техкарты и нормы (адаптируется к реальности)
- Остатки при закупке не теряются (плюсуются)
- Видны скрытые потери при ревизиях (недостачи, порча, хищения)
- Владелец видит себестоимость каждой услуги

## 2. Таблицы базы данных и их структура

### 2.1 Таблица: `inventory_items` — Справочник товаров

**Назначение:** Хранит все виды расходных материалов и их текущее состояние

| Колонка | Тип данных | Что хранится | Пример |
|---------|-----------|--------------|--------|
| `id` | INT PRIMARY KEY | Уникальный ID товара | 1 |
| `name` | VARCHAR(255) NOT NULL | Название материала | Шампунь Koch |
| `unit` | VARCHAR(50) | Единица измерения | канистра, литр, упаковка, бутылка |
| `current_qty` | DECIMAL(10, 2) | Текущий остаток на складе | 16.5 |
| `last_peak_qty` | DECIMAL(10, 2) | Пиковый остаток (эталон 100%) | 20.0 |
| `price_per_unit` | DECIMAL(10, 2) | Цена за одну единицу | 2500.00 |
| `category` | VARCHAR(100) | Группа товара (шампуни, воски, чернения) | shampoos |
| `is_active` | BOOLEAN | Товар ещё используется? | true |
| `last_updated_at` | TIMESTAMP | Когда последний раз обновили | 2026-01-15 10:30:00 |
| `notes` | TEXT | Заметки (поставщик, телефон, сроки) | Поставщик: Иван +7-999-111 |

**Логика:**
- При приходе товара: `current_qty += приход_кол_во` И `last_peak_qty = current_qty`
- При ревизии: только `current_qty = введённое_значение`
- `last_peak_qty` НЕ меняется при ревизии (служит эталоном для 100%)

---

### 2.2 Таблица: `inventory_log` — История всех операций

**Назначение:** Полная хронология всех движений товара (списания, приходы, ревизии, потери)

| Колонка | Тип данных | Что хранится | Пример |
|---------|-----------|--------------|--------|
| `id` | INT PRIMARY KEY | Уникальный ID операции | 1 |
| `inventory_item_id` | INT FOREIGN KEY | Ссылка на товар из `inventory_items` | 1 |
| `operation_type` | ENUM | Тип операции | incoming / usage / revision / manual_adjustment |
| `qty_before` | DECIMAL(10, 2) | Остаток ДО операции | 20.0 |
| `qty_after` | DECIMAL(10, 2) | Остаток ПОСЛЕ операции | 16.0 |
| `quantity_changed` | DECIMAL(10, 2) | На сколько изменилось (+ приход или - расход) | +30 (приход) или -4 (расход) |
| `peak_qty_before` | DECIMAL(10, 2) | Пиковый остаток ДО операции | 20.0 |
| `peak_qty_after` | DECIMAL(10, 2) | Пиковый остаток ПОСЛЕ операции | 32.0 (если был приход) |
| `loss_qty` | DECIMAL(10, 2) | Недостача при ревизии (если есть) | 2.0 (2 канистры потеряны) |
| `reason_note` | VARCHAR(255) | Описание: что произошло | Открыли новую / Ревизия по факту / Приход от Ивана |
| `created_at` | TIMESTAMP | Дата и время операции | 2026-01-15 10:30:00 |
| `created_by_user_id` | INT FOREIGN KEY | Кто это сделал (админ ID) | 5 |

**Логика:**
- Каждая операция (списание, ревизия, приход) = одна строка в логе
- `quantity_changed` может быть положительным (приход) или отрицательным (расход/потеря)
- `loss_qty` заполняется ТОЛЬКО при ревизии и ТОЛЬКО если обнаружена недостача

### 2.3 Таблица: `inventory_revisions` — Отдельный лог ревизий (опционально, для анализа)

**Назначение:** Более детальное хранение информации о ревизиях для отчётов

| Колонка | Тип данных | Что хранится | Пример |
|---------|-----------|--------------|--------|
| `id` | INT PRIMARY KEY | Уникальный ID ревизии | 1 |
| `inventory_item_id` | INT FOREIGN KEY | Какой товар пересчитали | 1 |
| `revision_date` | DATE | Дата ревизии | 2026-01-15 |
| `system_qty` | DECIMAL(10, 2) | Что система думала | 16.0 |
| `actual_qty` | DECIMAL(10, 2) | Что на самом деле | 14.0 |
| `loss_qty` | DECIMAL(10, 2) | Разница (недостача) | 2.0 |
| `loss_reason` | VARCHAR(255) | Почему потеряно (опционально) | Пролили, украли, испортилось |
| `days_since_last_peak` | INT | Дней прошло с последней закупки | 3 |
| `days_since_last_revision` | INT | Дней прошло с последней ревизии | 3 |
| `expected_consumption` | DECIMAL(10, 2) | Расход по расчёту | 4.5 |
| `actual_consumption` | DECIMAL(10, 2) | Реальный расход (с потерями) | 6.0 |
| `created_by_user_id` | INT FOREIGN KEY | Кто делал ревизию | 5 |

**Логика:**
- Каждая ревизия = одна строка
- `loss_qty = system_qty - actual_qty`
- Используется для анализа потерь и отчётов

---

### 2.4 Таблица: `service_costs` — Расходы по услугам (для себестоимости)

**Назначение:** Связь между услугами (мойка, шиномонтаж, чернение) и материалами, которые используются

| Колонка | Тип данных | Что хранится | Пример |
|---------|-----------|--------------|--------|
| `id` | INT PRIMARY KEY | Уникальный ID | 1 |
| `service_id` | INT FOREIGN KEY | Ссылка на услугу из таблицы услуг | 1 (Мойка стандарт) |
| `inventory_item_id` | INT FOREIGN KEY | Какой материал используется | 1 (Шампунь Koch) |
| `cost_per_service_unit` | DECIMAL(10, 2) | Сколько товара расходуется на 1 услугу | 0.5 (полканистры на одну мойку) |
| `is_primary_cost` | BOOLEAN | Это основной материал для услуги? | true |
| `cost_priority` | INT | Порядок при отображении | 1 |

**Логика:**
- Если услуга "Комплекс мойка" использует 0.5л шампуня и 0.1л воска, это записывается здесь
- Используется для расчёта себестоимости конкретной услуги
- Или можно считать себестоимость просто по общему расходу / количество машин

**Альтернатива (без этой таблицы):** Считаем себестоимость по общей формуле (ниже в разделе 4)

## 3. Формулы расчётов

### 3.1 Основная формула расхода (для отчётов)

```
Расход_за_период = Остаток_на_начало + Приход - Остаток_на_конец

Где:
- Остаток_на_начало = last_peak_qty ИЛИ quantity из последней ревизии
- Приход = сумма всех incoming операций за период
- Остаток_на_конец = current_qty ИЛИ quantity из текущей ревизии
```

**Пример:**
```
Период: 15.01 - 15.01 (3 дня)
Шампунь Koch:
- На 13.01 утром: 20 канистр (последняя ревизия)
- За период привезли: 5 канистр (приход 14.01)
- На 15.01 вечером: 14 канистр (текущее состояние)

Расход = 20 + 5 - 14 = 11 канистр за 3 дня
```

---

### 3.2 Себестоимость на одну машину

```
Себестоимость_материалов = Расход_в_рублях / Количество_машин

Где:
- Расход_в_рублях = Расход_в_единицах × price_per_unit
- Количество_машин = COUNT(заказов) за тот же период
```

**Пример:**
```
Период: 3 дня
- Расход шампуня: 11 канистр × 2500₽ = 27500₽
- Расход воска: 3л × 800₽ = 2400₽
- Расход чернения: 2.5л × 600₽ = 1500₽
- Итого расход материалов: 31400₽

- Машин помыли: 150 шт

Себестоимость_материалов = 31400 / 150 = 209₽ на одну машину
```

---

### 3.3 Процент прогресс-бара на складе

```
Процент = (current_qty / last_peak_qty) × 100

Если last_peak_qty = 0 (нет данных) → percentage = 0%
```

---

### 3.4 Средний расход в день

```
Дней_прошло = TODAY - дата_последнего_поступления
Расход_в_день = Расход_за_период / Дней_прошло

Пример:
- Приход был 12.01 (20 канистр)
- Сегодня 15.01
- Дней прошло = 3
- Расход = 6 канистр
- Расход_в_день = 6 / 3 = 2 канистры в день
```

---

### 3.5 Прогноз дней до нулевого остатка

```
Дней_до_нуля = current_qty / Расход_в_день

Если расход_в_день = 0 → бесконечность (показываем "∞" или "Не используется")

Пример:
- Сейчас: 14 канистр
- Расход: 2 кан/день
- Дней до нуля: 14 / 2 = 7 дней
```

---

### 3.6 Потери при ревизии (недостача)

```
Потеря_за_период = sum(loss_qty) где operation_type = 'revision'

Потеря_% = (Потеря_за_период / Расход_за_период) × 100
```

**Пример:**
```
Период: месяц
- Расход шампуня по формуле: 50 канистр
- При 4 ревизиях обнаружено недостач: 2, 1, 0.5, 1.5 = 5 канистр
- Потеря % = 5 / 50 × 100 = 10% (много! нужно разбираться)
```

---

### 3.7 Себестоимость в процентах от выручки

```
Процент_материалов = (Расход_в_рублях / Выручка) × 100

Норма для автомойки: 2-5% от выручки
```

**Пример:**
```
- Выручка за 3 дня: 45000₽
- Расход материалов: 31400₽
- Процент: 31400 / 45000 × 100 = 69.7% (ОЧЕНЬ МНОГО! Проверить расчёты)

Нормально должно быть 2000-3000₽ за 3 дня при выручке 45000₽
```

## 4. Виды отчётов для владельца

### 4.1 Отчёт "Состояние склада" (Общий обзор)

**Когда смотреть:** Каждый день, утром

**Что показывать:**
- Список всех товаров с прогресс-барами
- % по каждому товару
- Дней до конца запаса
- Дата последней ревизии
- Дата последнего поступления

**Таблица в отчёте:**

| Материал | Ед. | Сейчас | Макс | % | Расход/день | Дней | Ревизия | Приход |
|----------|-----|--------|------|---|------------|------|---------|--------|
| Шампунь Koch | кан | 14 | 20 | 70% | 2.0 | 7 | 15.01 | 12.01 |
| Воск | л | 1.5 | 2 | 75% | 0.3 | 5 | 14.01 | 10.01 |
| Чернение | л | 3 | 5 | 60% | 0.5 | 6 | 14.01 | 08.01 |
| Микрофибра | шт | 2 | 3 | 67% | 0.2 | 10 | 12.01 | 05.01 |

**Формулы в отчёте:**
- Сейчас = current_qty
- Макс = last_peak_qty
- % = (current_qty / last_peak_qty) × 100
- Расход/день = расход за последние 7 дней / 7
- Дней = current_qty / расход_в_день
- Ревизия = дата последней ревизии
- Приход = дата последнего поступления

---

### 4.2 Отчёт "Расход материалов" (Анализ расходов)

**Когда смотреть:** Раз в неделю или раз в месяц

**Что показывать:**
- Сколько потрачено по каждому материалу (в рублях и количестве)
- Расход на одну машину
- Потери и недостачи
- Тренд (растёт / падает расход)

**Таблица в отчёте (за месяц):**

| Материал | Расход шт | Цена шт | Расход ₽ | Машин | На 1 машину ₽ | Потери | Потери % |
|----------|----------|---------|----------|-------|--------------|--------|----------|
| Шампунь | 45 кан | 2500₽ | 112500₽ | 1200 | 93.75₽ | 3 кан | 6.7% |
| Воск | 12 л | 800₽ | 9600₽ | 1200 | 8₽ | 0.5л | 4.2% |
| Чернение | 8 л | 600₽ | 4800₽ | 1200 | 4₽ | 0 | 0% |
| Микрофибра | 6 шт | 1200₽ | 7200₽ | 1200 | 6₽ | 1 шт | 14.3% |
| **ИТОГО** | — | — | **134100₽** | 1200 | **111.75₽** | — | **~6%** |

**Формулы в отчёте:**
- Расход шт = sum(quantity_changed) где operation_type = 'usage'
- Расход ₽ = Расход шт × price_per_unit
- На 1 машину ₽ = Расход ₽ / Количество машин
- Потери = sum(loss_qty) где operation_type = 'revision'
- Потери % = (Потери / (Расход шт + Потери)) × 100

---

**Когда смотреть:** Раз в неделю (чтобы отслеживать рост цен)

**Что показывать:**
- Расход материалов на каждый тип услуги
- Себестоимость
- Процент от средней цены услуги
- Норма ли это

**Таблица в отчёте:**

| Услуга | Кол-во | Расход ₽ | Себест. ₽ | % от цены |
|--------|--------|----------|----------|-----------|
| Стандарт мойка | 600 | 56250₽ | 93.75₽ | 6.25% (цена 1500₽) |
| Премиум мойка | 400 | 56250₽ | 140.63₽ | 4.69% (цена 3000₽) |
| Шиномонтаж | 120 | 14400₽ | 120₽ | 12% (цена 1000₽) |
| Чернение | 80 | 4800₽ | 60₽ | 6% (цена 1000₽) |

**Логика:**
- Если у тебя в `service_costs` записано, что "Стандарт мойка" использует 0.5л шампуня + 0.05л воска, считаем по этому
- Или просто делим общий расход пропорционально количеству услуг

### 4.4 Отчёт "Финансовый анализ" (Главное число для владельца)

**Когда смотреть:** Раз в неделю или месяц

**Что показывать:**
- Выручка
- Расход материалов
- % материалов от выручки
- Норма ли это

**Таблица в отчёте (за месяц):**

| Показатель | Сумма | % от выручки | Статус |
|------------|-------|-------------|--------|
| **Выручка** | 450000₽ | 100% | — |
| **Расход материалов** | 9900₽ | 2.2% | ✅ Отлично |
| **Расход по ревизиям** | 900₽ | 0.2% | ⚠️ Проверить |
| **Расход ОС и персонал** | 150000₽ | 33% | ✅ Норма |
| **МАРЖА** | 289200₽ | 64.3% | ✅ Норма |

**Интерпретация для владельца:**
- 2.2% на материалы — хорошо (норма 2-5%)
- 0.2% потерь при ревизиях — нормально (в пределах 1%)
- 64% маржа — отличный результат

**Формулы:**
- Выручка = sum(заказов) за период
- Расход материалов = sum всех incoming
- Расход по ревизиям = sum(loss_qty) × price_per_unit
- % = (Расход / Выручка) × 100

### 4.5 Отчёт "Тренды и прогнозы" (Куда идти)

**Когда смотреть:** Раз в неделю (следить за тенденциями)

**Что показывать:**
- Как меняется расход (растёт / падает)
- Прогноз на следующий месяц
- Какие товары скоро закончатся

**Таблица в отчёте:**

| Материал | Неделя 1 | Неделя 2 | Неделя 3 | Неделя 4 | Тренд | Прогноз |
|----------|----------|----------|----------|----------|-------|---------|
| Шампунь | 11 кан | 12 кан | 13 кан | 14 кан | ⬆️ | +20% (35 кан/мес) |
| Воск | 3 л | 3 л | 2.5 л | 2.8 л | → | Стабильно ~3л/нед |
| Чернение | 2 л | 1.5 л | 1 л | 1.2 л | ⬇️ | -40% (2.5 л/мес) |

**Логика:**
- Считаешь расход по неделям (берёшь данные из `inventory_log`)
- Считаешь тренд (line regression или просто сравниваешь неделю к неделе)
- Прогноз = последний тренд × 4 недели

---

### 4.6 Отчёт "Недостачи и потери" (Аудит)

**Когда смотреть:** Раз в неделю (следить за хищениями и ошибками)

**Что показывать:**
- Какие товары теряют
- На сколько процентов
- В какие дни обнаружили потери

**Таблица в отчёте:**

| Дата | Материал | Система | Факт | Потеря | % | Примечание |
|------|----------|---------|------|--------|---|-----------|
| 12.01 | Шампунь | 20 | 18 | 2 кан | 10% | — |
| 14.01 | Воск | 1.5 | 1.2 | 0.3л | 20% | Вероятно пролили |
| 15.01 | Микрофибра | 5 | 4 | 1 шт | 20% | — |

**Интерпретация:**
- 10-20% потеря за период = нормально (используют, могут пролить)
- 30%+ = нужно разбираться (либо воруют, либо считаешь неправильно)

**Формулы:**
- Потеря = system_qty - actual_qty (из таблицы `inventory_revisions`)
- % = (Потеря / system_qty) × 100

## 5. Как получить данные для каждого отчёта

### Отчёт 1: Состояние склада
**Источник:** `inventory_items` + расчёты на основе `inventory_log`
```
SELECT 
  name, unit, current_qty, last_peak_qty,
  (current_qty / last_peak_qty * 100) as percent,
  расход_в_день (из последних 7 дней),
  current_qty / расход_в_день as дней_до_конца,
  MAX(created_at) as дата_ревизии (где operation_type = 'revision'),
  MAX(created_at) as дата_приходa (где operation_type = 'incoming')
FROM inventory_items
```

### Отчёт 2: Расход материалов
**Источник:** `inventory_log` за период
```
SELECT
  name,
  SUM(quantity_changed) as расход_шт,
  SUM(quantity_changed * price_per_unit) as расход_рубли,
  SUM(loss_qty) as потери,
  COUNT(машин) as машин_за_период
FROM inventory_log
WHERE created_at BETWEEN start_date AND end_date
GROUP BY inventory_item_id
```

### Отчёт 3: Себестоимость услуг
**Источник:** `service_costs` + `inventory_items` + COUNT(заказов)
```
SELECT
  service_name,
  COUNT(orders) as кол_во_услуг,
  SUM(cost_per_service_unit * price_per_unit) as себестоимость
FROM service_costs
JOIN inventory_items ON service_costs.inventory_item_id = inventory_items.id
WHERE service_id = X
```

### Отчёт 4: Финансовый анализ
**Источник:** `inventory_log` + `orders` (выручка)
```
SELECT
  SUM(orders.price) as выручка,
  SUM(inventory_log.quantity_changed * price_per_unit) as расход_материалов,
  SUM(inventory_log.loss_qty * price_per_unit) as потери
FROM orders
JOIN inventory_log ON orders.created_at = inventory_log.created_at
WHERE period = MONTH
```

### Отчёт 5: Тренды
**Источник:** `inventory_log` с группировкой по неделям
```
SELECT
  WEEK(created_at) as неделя,
  inventory_item_id,
  SUM(quantity_changed) as расход_за_неделю
FROM inventory_log
WHERE operation_type IN ('usage', 'revision')
GROUP BY WEEK(created_at), inventory_item_id
ORDER BY неделя DESC
```

### Отчёт 6: Недостачи
**Источник:** `inventory_revisions`
```
SELECT
  revision_date,
  name,
  system_qty,
  actual_qty,
  loss_qty,
  (loss_qty / system_qty * 100) as loss_percent,
  loss_reason
FROM inventory_revisions
JOIN inventory_items ON inventory_revisions.inventory_item_id = inventory_items.id
ORDER BY revision_date DESC
```

## 6. Нюансы и правила для отчётов

### Правило 1: Период выбирает владелец
- День (сегодня)
- Неделя (текущая неделя или выбранная)
- Месяц (текущий месяц или выбранный)
- Пользовательский диапазон (от... до...)

### Правило 2: Расход считаем из ревизий, не из нажатия кнопок
- Нажатие кнопки `[-1 Открыли]` — это приблизительно
- Ревизия — это правда
- На отчётах используем только данные из `inventory_revisions` (где есть проверенные остатки)

### Правило 3: Потери видны только при ревизии
- Если админ не делал ревизию, потерь "нет" в отчёте
- Потери = разница между расчётным и реальным остатком

### Правило 4: Себестоимость растёт, если:
- Больше услуг одного типа (мойки дешевле шиномонтажа по материалам)
- Материалы подорожали (price_per_unit вырос)
- Больше потерь при ревизиях (воруют / неправильно считаем)

### Правило 5: Норма для автомойки
- Материалы: 2-5% от выручки
- Потери: 0-1% от расхода
- Маржа: 50-70% (зависит от условий)

## 7. Пример полного цикла за неделю

### Понедельник, 12 января, 08:00
**Ревизия материалов:**
- Шампунь: было 30, приход 0, сейчас 28 → остаток вводим 28, потеря 2
- Воск: было 3л, приход 0, сейчас 2.8л → остаток вводим 2.8, потеря 0.2л

**В системе:**
```
inventory_items:
- Шампунь: current_qty = 28, last_peak_qty = 30
- Воск: current_qty = 2.8, last_peak_qty = 3

inventory_revisions:
- Шампунь: system_qty = 30, actual_qty = 28, loss_qty = 2
- Воск: system_qty = 3, actual_qty = 2.8, loss_qty = 0.2
```

### Понедельник-пятница, 12-16 января
**Ежедневная работа:**
- Админ нажимает кнопки `[-1 Открыли]` каждый день
- Записывается в `inventory_log` как usage
- `current_qty` медленно падает

### Суббота, 17 января, 18:00
**Вторая ревизия:**
- Шампунь: система показывает 23, админ пересчитал 22 → потеря 1
- Воск: система показывает 2.4л, админ пересчитал 2.35л → потеря 0.05л

**В системе:**
```
inventory_revisions:
- Шампунь: system_qty = 23, actual_qty = 22, loss_qty = 1, days_since_last_peak = 5
- Воск: system_qty = 2.4, actual_qty = 2.35, loss_qty = 0.05, days_since_last_peak = 5
```

### Вторник, 19 января, 10:00
**Отчёт владельцу за неделю:**

| Материал | Было | Приход | Потери | Расход | На машину |
|----------|------|--------|--------|--------|-----------|
| Шампунь | 28 | 0 | 3 | 6 кан | ~50₽ |
| Воск | 2.8л | 0 | 0.25л | 0.5л | ~3₽ |

Себестоимость за неделю: 150 машин × 50₽ шампунь + 3₽ воск = ~8000₽ материалов на выручку 75000₽ = 10.7% (нормально).

## 8. Резюме: Что нужно собирать и считать

### Собираем:
1. **При приходе товара:** кол-во + дата → `inventory_log.incoming`
2. **При ревизии:** реальный остаток + дата → `inventory_revisions`
3. **Из внешних систем:** количество услуг (машин) за период → `orders`

### Считаем в отчётах:
1. Расход = Начало + Приход - Конец
2. Себестоимость = Расход ₽ / Кол-во машин
3. Потери = Система - Факт (при ревизии)
4. % от выручки = Расход ₽ / Выручка × 100
5. Тренды = Расход по неделям / месяцам
6. Прогнозы = Текущий тренд × период

### Показываем владельцу:
1. Состояние склада (прогресс-бары)
2. Расход по материалам (в рублях и штуках)
3. Себестоимость услуг (на одну машину)
4. Финансовую картину (% от выручки)
5. Тренды (что растёт, что падает)
6. Недостачи (где потери, почему)

## 9. Минимальный набор таблиц для старта

Чтобы заработала вся система, достаточно **3 таблицы:**

1. **`inventory_items`** — справочник товаров (колонки: id, name, unit, current_qty, last_peak_qty, price_per_unit, category, notes)
2. **`inventory_log`** — лог операций (колонки: id, inventory_item_id, operation_type, qty_before, qty_after, quantity_changed, loss_qty, reason_note, created_at, created_by_user_id)
3. **`inventory_revisions`** — ревизии для отчётов (колонки: id, inventory_item_id, revision_date, system_qty, actual_qty, loss_qty, days_since_last_peak, expected_consumption, actual_consumption)

Таблица `service_costs` — опциональна (нужна только если хочешь себестоимость по типам услуг, а не общий расход на машину).
